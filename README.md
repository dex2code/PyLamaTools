# PyLamaTools

Простой чат-оркестратор с возможностью расширения локальных инструментов.

---

## Требования

- **Ollama** – сервер с запущенной моделью (API URL задаётся в `config.py`).
- **Python 3.10+** – для создания виртуального окружения.
- **Git** – для клонирования репозитория.
- Очень рекомендуется модель семейства qwen3.5+ как максимально подходящая для работы с инструментами

---

## Установка и запуск

Выполните последовательно команды в терминале:

```bash
# 1. Клонируйте репозиторий
git clone https://github.com/dex2code/PyLamaTools.git

# 2. Перейдите в папку проекта
cd ./PyLamaTools

# 3. Создайте виртуальное окружение
python3 -m venv ./.venv

# 4. Активируйте виртуальное окружение
source ./.venv/bin/activate

# 5. Обновите pip до актуальной версии
pip install --upgrade pip

# 6. Установите зависимости
pip install -r ./requirements.txt

# 7. Запустите приложение
python3 -m main
```

## Конфигурация LLM-чата – описание параметров

Ниже приведено подробное описание всех параметров, используемых в файле конфигурации для работы с языковой моделью (Ollama) и системой инструментов.

<pre>
settings = {
    "log_level": "WARNING",
    "tools_dir": "tools",
    "system_prompt_file": "system_prompt.txt",
    "system_prompt_file_enc": "utf-8",
    "ollama_url": "http://127.0.0.1:11434",
    "ollama_model": "qwen3.5:9b",
    "tool_iterations": 16,
    "context_max_tokens": 0,
    "context_encoding": "cl100k_base",
    "display_thinking": True,
    "model_thinking": True,
    "options": {
        "temperature": 1,
        "top_k": 20,
        "top_p": 0.95
    }
}
</pre>

---

## `log_level` (строка)
**Значение по умолчанию:** `"WARNING"`  
**Назначение:**  
Уровень логирования для всего приложения. Определяет, какие сообщения будут выводиться в консоль или лог-файл. Возможные значения (стандартные для Python logging): `"DEBUG"`, `"INFO"`, `"WARNING"`, `"ERROR"`, `"CRITICAL"`.  
`WARNING` – минимальный уровень, при котором в лог попадают только предупреждения и ошибки, что снижает шум при работе.

---

## `tools_dir` (строка)
**Значение по умолчанию:** `"tools"`  
**Назначение:**  
Путь к директории, в которой находятся Python-файлы с функциями-навыками (инструментами) для LLM. Система сканирует эту папку, импортирует все модули и регистрирует их описания (`tool_description`) для передачи модели в запросах.

---

## `system_prompt_file` (строка)
**Значение по умолчанию:** `"system_prompt.txt"`  
**Назначение:**  
Имя файла, содержащего системный промпт (инструкцию для модели). Этот текст загружается при старте и вставляется в начало каждого диалога, чтобы задать поведение, роль и контекст для LLM.

---

## `system_prompt_file_enc` (строка)
**Значение по умолчанию:** `"utf-8"`  
**Назначение:**  
Кодировка файла системного промпта. Указывает, в какой кодировке читать файл (например, `"utf-8"`, `"cp1251"`). Это гарантирует корректную обработку символов, особенно не-ASCII.

---

## `ollama_url` (строка)
**Значение по умолчанию:** `"http://127.0.0.1:11434"`  
**Назначение:**  
Базовый URL для подключения к локальному или удалённому серверу Ollama. Используется для отправки запросов к API модели. По умолчанию указывает на локальный экземпляр, запущенный на стандартном порту.

---

## `ollama_model` (строка)
**Значение по умолчанию:** `"qwen3.5:9b"`  
**Назначение:**  
Имя модели, которую использует Ollama для генерации ответов. Это может быть любая модель, загруженная в Ollama (например, `"llama3.2:3b"`, `"mistral:7b"`). Указывает, какую именно версию и размерность вызывать.

---

## `tool_iterations` (целое число)
**Значение по умолчанию:** `16`  
**Назначение:**  
Максимальное количество итераций (циклов вызова инструментов) в рамках одного диалогового сеанса. Если модель решает вызвать функцию, система выполняет её, возвращает результат и снова обращается к модели, пока не будет получен финальный ответ или не исчерпается лимит. Этот параметр предотвращает бесконечные циклы и контролирует глубину взаимодействия.

---

## `context_max_tokens` (целое число)
**Значение по умолчанию:** `0`  
**Назначение:**  
Максимальное количество токенов, которое может занимать история диалога (контекст). Если история превышает этот порог, система обрезает самые старые сообщения. Значение `0` означает отсутствие ограничений (используется лимит самой модели). Полезно для экономии памяти и предотвращения потери важной информации из-за слишком длинных диалогов.

---

## `context_encoding` (строка)
**Значение по умолчанию:** `"cl100k_base"`  
**Назначение:**  
Токенизатор, используемый для подсчёта количества токенов в тексте. Указывает алгоритм разбиения строк на токены, соответствующий конкретной модели (например, для GPT-4 используется `"cl100k_base"`). Необходим для точного вычисления длины контекста и соблюдения лимитов `context_max_tokens`.

---

## `display_thinking` (булево)
**Значение по умолчанию:** `True`  
**Назначение:**  
Определяет, следует ли показывать пользователю внутренние "размышления" модели или промежуточные шаги (например, логи вызова функций, сообщения о прогрессе). Включает более подробный вывод в интерфейс, что полезно для отладки или обучения, но может быть отключено для чистого интерфейса.

---

## `model_thinking` (булево)
**Значение по умолчанию:** `True`  
**Назначение:**  
Разрешает модели использовать "режим размышления" (если поддерживается). В некоторых моделях (например, DeepSeek-R1) есть специальный тег или возможность вывода цепочки рассуждений перед финальным ответом. Этот параметр включает передачу соответствующего флага в API, чтобы модель могла генерировать поясняющие промежуточные тексты.

---

## `options` (словарь)
**Значение по умолчанию:**
```json
{
    "temperature": 1,
    "top_k": 20,
    "top_p": 0.95
}
```
**Назначение:**  
Набор параметров, напрямую передаваемых в API Ollama для управления генерацией текста:

- **`temperature`** (число, 0–2) – контролирует случайность выбора токенов. Чем выше значение, тем более разнообразные и креативные ответы; `1` – нейтральное значение.
- **`top_k`** (целое) – ограничивает выборку только токенами с наивысшими вероятностями (например, только топ-20). Уменьшает вероятность "бредовых" вариантов.
- **`top_p`** (число 0–1) – ядерное (nucleus) семплирование: выбираются токены, чья кумулятивная вероятность не превышает заданный порог. Значение `0.95` даёт баланс между разнообразием и качеством.

Эти параметры тонко настраивают стиль и предсказуемость ответов модели.

# Расширение функционала

Краткая инструкция для создания функций-навыков, совместимых с OpenAI Function Calling.

---

## 1. Общие требования

- Каждый навык – отдельный Python-модуль.
- Функция должна иметь аннотации типов для всех аргументов и возвращаемого значения.
- Функция должна иметь подробное описания для LLM.

---

## 2. Сигнатура и документация

```python
def my_tool(param1: str, param2: int = 42) -> Dict[str, Any]:
    """
    Краткое описание.

    Args:
        param1: Описание.
        param2: Описание (необязательный).

    Returns:
        Словарь с полями:
            - success (bool)
            - error (Optional[str])
            - ... (дополнительные поля)
    """
```

---

## 3. Обработка ошибок

- Явно проверяйте входные данные и возвращайте словарь с `success=False` и сообщением в `error`.
- Все исключения должны быть перехвачены (либо явно, либо через `@logger.catch`).
- При ошибке все дополнительные поля заполняйте значениями по умолчанию (пустые списки, 0, `None`).

**Шаблон:**

```python
@logger.catch(reraise=False)
def my_tool(...) -> Dict[str, Any]:
    if not condition:
        return {"success": False, "error": "...", "data": [], "count": 0}
    try:
        # основная логика
        return {"success": True, "error": None, "data": result, "count": len(result)}
    except Exception as e:
        return {"success": False, "error": str(e), "data": [], "count": 0}
```

---

## 4. Возвращаемое значение

Словарь **обязан** содержать:

- `success` (bool)
- `error` (Optional[str]) – `None` при успехе, иначе описание проблемы.

Дополнительные поля (например, `files`, `data`, `count`) определяются разработчиком и должны быть описаны в docstring и описании.

---

## 5. Описание инструмента для LLM (`tool_description`)

Добавьте атрибут к функции:

```python
my_tool.tool_description = {
    "type": "function",
    "function": {
        "name": "module_name.my_tool",
        "description": "Что делает инструмент",
        "parameters": {
            "type": "object",
            "properties": {
                "param1": {"type": "string", "description": "..."},
                "param2": {"type": "integer", "description": "...", "default": 42}
            },
            "required": ["param1"],
            "additionalProperties": False
        }
    }
}
```

- Все параметры должны быть описаны в `properties`, их типы и `default` (если есть).
- Обязательные параметры перечислены в `required`.

---

## 6. Чек-лист перед сдачей

- [ ] Добавлены все импорты (включая `annotations`).
- [ ] Есть аннотации типов.
- [ ] Написана docstring с `Args` и `Returns`.
- [ ] Возвращаемый словарь содержит `success` и `error`.
- [ ] Ошибки обработаны и возвращают структуру с дефолтными значениями.
- [ ] Определён атрибут `tool_description` в формате OpenAI.
- [ ] Код протестирован на корректных и некорректных данных.
